## R09-A mask design boundary

The current `GeometryMask` is a version-1 hard clip of final Path/Text geometry in Composition space. Its source paint, opacity and ordinary visibility do not affect clip coverage. The source is retained independently of the target and the native 0.25 writer keeps it editable. Group processing evaluates children first, then Group Posterize, then geometry mask, opacity and blend. `SetMask`, normal Properties and SVG projection all use that geometry contract. REQ-192/201 hidden-source access is already present in the UI.

An alpha or luma mask needs a distinct authored mode and an explicit pixel input stage. Before implementation, select whether source coverage uses raw asset alpha, the source's evaluated appearance, or another declared stage; define source effect/opacity/visibility behavior, Composition-space transform and sampling, group/postchildren order, premultiplication, sRGB versus linear luma, bit depth, bounds, cycles, and old/new native handling. A source-only alpha mode from Image pixels would not by itself satisfy the arbitrary Path/Object/Image source or mask-stack Candidates. Preserve the original native source; unsupported SVG/other derivatives must state loss or refuse. This is a **local DESIGN_GATE** for the alpha/luma edge and its Candidate adoption, with these decisions as the resume trigger. It does not block the independent Confirmed analysis edge below.

## R09-D1 approved bounded contract

- Add a read-only `analyze_regions` request to the live desktop API and formal MCP adapter. It requires exact live session/document identity and expected revision. Inputs are Composition, Artboard, finite scale in `(0,16]` pixels per document unit, and integer alpha threshold `[1,255]`. It uses `Canvas::render_artboard` with a transparent backdrop at the committed revision, so the exact existing artwork renderer determines rasterization, effects, masks, blends and crop. Active gesture drafts refuse. No file read/write or Session commit occurs.
- Treat a pixel as foreground when its **output alpha byte** is greater than or equal to threshold. Find deterministic 4-connected components in row-major seed order. Report for each component its area in output pixels and integer `x,y,width,height` bounds, where `(0,0)` is the Artboard output's top-left and width/height are exclusive extents. Report threshold, connectivity, scale, image dimensions, color/alpha domain and source revision. This is a replaceable derived result, not persistent authored geometry or a stable object identity. A white export background is never an analysis input.
- Limit the analysis image to 4,000,000 output pixels and at most 10,000 components; refuse larger results with `ANALYSIS_LIMIT` before publishing any partial result. Keep the existing renderer's limits and errors visible. Invalid/fractional/zero threshold, stale identity/revision, gesture, unknown fields and missing Artboard refuse without mutation.
- Independent oracle: an 8-bit transparent 8×6 image with two disjoint opaque rectangles, `[1,1]` to `[2,2]` and `[5,2]` to `[7,4]`, gives two regions with areas 4 and 9 and bounds `(1,1,2,2)` and `(5,2,3,3)` at threshold 128. A diagonal-only touch remains two components. A 127-alpha pixel is absent at 128 and present at 127. Verify API and MCP return the same structured result and revision, and that native bytes/history are unchanged. Test real Canvas input as well as the independent component oracle.

Residuals: This does not add edge/contour extraction, threshold/color grouping beyond alpha, mask boolean/morphology, Node reuse, GUI analysis authoring, saved region candidates, vector tracing, full REQ-64/65/66, AE blend parity or human hands-on acceptance. Those remain separate Route obligations.

## Implementation and review

The deterministic pixel helper returns area/bounds and domain metadata. The formal `nect_analyze_regions` MCP tool forwards the same read-only request. No native writer, schema, authored Document or Session command was changed.
