## Bounded contract

- Add optional Boolean `include_color_groups` to the existing read-only `analyze_regions` desktop request and formal `nect_analyze_regions` schema. Omitted or `false` preserves the existing result and all D1–D7 behavior. A non-Boolean value rejects as `INVALID_REQUEST`. `true` requests `color_groups` after the existing D1–D7 analysis and cap checks, from the **same** committed transparent Canvas render, same alpha threshold, dimensions, scale and revision. No second render, authored state or native change.
- Convert the output image's `ARGB32_Premultiplied` pixels to 8-bit straight sRGB (`ARGB32`) once for grouping. A pixel participates only when the original output alpha byte is `>= threshold`. Key by the converted exact `[r,g,b]` bytes; alpha is a selection threshold, not a group key. This is byte-exact output-color grouping, not authored palette identity, perceptual matching, ICC conversion or semantic segmentation. Declare `color_key_domain:"output-srgb-straight-rgb8"` and `color_alpha_rule:"output-alpha-byte-ge-threshold"` in the added result metadata.
- Return `color_groups` as an array sorted by ascending numeric RGB key. Each group has `rgb:[r,g,b]`, `area`, `bounds:{x,y,width,height}` and row-major maximal horizontal `runs:[{y,x,width}]`; coordinates are output pixels with top-left origin and exclusive widths/heights. `area` is the count of qualifying pixels and equals summed run widths. The enclosing result supplies width, height, threshold, scale, source revision, alpha domain and coordinate space. Empty foreground gives an empty array.
- At most 256 distinct groups and 20,000 total color runs across groups. Refuse group 257 or run 20,001 with `ANALYSIS_LIMIT`, no partial API/MCP result and no Document/revision/History/native-byte change. Existing D1–D7 refusal precedence stays first. Validate identity, revision, gesture, scale, threshold and unknown fields as before. No GUI control, new file operation, Session command or dependency.

## Independent oracles

1. A 4×3 transparent image with opaque red at `(0,0),(1,0),(3,2)` and opaque blue at `(2,0),(2,1)` yields two RGB-sorted groups. Blue `[0,0,255]` area 2, bounds `(2,0,1,2)`, runs `{0,2,1},{1,2,1}`; red `[255,0,0]` area 3, bounds `(0,0,4,3)`, runs `{0,0,2},{2,3,1}`. Transparent pixels do not participate. A valid premultiplied alpha-127 red pixel is excluded at threshold 128 and included at 127, retaining the same straight RGB key.
2. An all-opaque 100×200 alternating red/blue checkerboard has one alpha-connected region, two color groups and exactly 20,000 total color runs; accept it. A 101×200 checkerboard has 20,200 runs and refuses, while every D1–D7 cap remains below its threshold. A 257×1 opaque image with 257 distinct RGB keys refuses group 257 while D1–D7 caps remain below threshold. Establish counts from input coordinates independently of the returned groups.
3. Check the pixel helper, real Canvas/API output from an embedded exact-color fixture, and formal MCP equality for a nonempty request. Test omitted/false parity, invalid optional-field type, helper limits and real Canvas/API refusal without a partial result or authored-state change. Automated Qt/API/MCP checks do not close hands-on GUI acceptance.

## Residuals

This does not bind pixels to authored palette IDs, merge nearby/perceptually similar colors, make color-group masks into authored state, combine named color groups with D7 operands, or close REQ-66/R09/P09/L2.
