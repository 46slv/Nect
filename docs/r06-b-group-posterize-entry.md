## Selected contract

- Add one built-in `nect.group.posterize` behavior version 1 with a stable instance ID to a Group's ordered operation stack. Its input is the premultiplied sRGB RGBA image obtained **after all children have evaluated their own operations and composited in Group order**. Its output is the same pixel domain. It is not applied to each child. The Group mask, Group opacity and blend are applied after this operator. Existing neutral Groups without enabled effects still pass through.
- One ordinary Scalar parameter `levels` is an integer in `[2,16]`, default 2. For pixels with alpha greater than zero, unpremultiply each straight sRGB channel, compute `floor(channel * (levels - 1) + 0.5) / (levels - 1)`, then premultiply by the unchanged alpha. For alpha zero emit transparent black. Keep the current 8-bit sRGB Canvas/PNG limits; no HDR or color-management claim. Disabled instances pass the exact input. Ordered multiple instances run in stack order, though this packet adds only one type.
- Reuse Session `AddOperation`, `Set`, `EnableOperation`, `ReorderOperations` and `RemoveOperation`, stable `op.<instance>.levels` references, Undo/revision validation and the existing API command path. The Effects panel must expose Group target/apply and the normal parameter/bypass/remove route; stale target or Session revision refuses atomically. Path, Text and Image refuse this type; Groups refuse Shape-local Offset/Fill/Stroke/Repeater. Do not create a second panel-owned effect state.
- Native writer advances additively to 0.25: Group gains its ordered stack with the same instance IDs, type/version, enabled and normal parameter Scalars as other operations. Decoding 0.1–0.24 gives an empty Group stack; a Group stack in a 0.24 document is invalid. Keep old schemas strict and provide a strict 0.25 schema. Unknown type/version and invalid `levels` refuse without fallback. This uses existing Object ownership, operation IDs and Session property machinery; it does not add graph or shared definitions.
- Canvas and PNG use the real postchildren pixels. SVG export of a document with an enabled Group Posterize must refuse explicitly until an exact vector/filter representation or opt-in bake exists. Native source remains editable. API export plans must disclose the unsupported derivative rather than silently omitting the effect. Bypassed Posterize allows ordinary SVG projection.

## Independent acceptance

1. Two overlapping 50%-alpha children, red below blue, produce a straight overlap color near `(85,0,170)` before Posterize. At two levels, the **postcomposite** overlap becomes blue `(0,0,255)` with the same 75%-alpha. Applying two-level Posterize to the children separately would leave the purple overlap; use this as the negative oracle. Single-child red and blue interiors remain red and blue. Check PNG/Canvas pixels away from antialias edges against independent arithmetic, not a second call to the product renderer.
2. Disable and remove return the original overlap; changing `levels` through Session/normal Properties changes only the derived result. One command has one revision and Undo restores the exact authored stack. Compare panel and API authored semantics and pixels. Cold native reopen retains Group/child source, instance ID/type/version/level/order/enabled and result. Old native migrates to an empty Group stack.
3. No selection, stale target/revision, Path/Text/Image target, Shape operation on Group, invalid/noninteger/out-of-range level, duplicate ID, unknown type/version and old-version smuggling refuse with unchanged Document/revision/history. SVG refusal names the unsupported effect and leaves native untouched. Renderer surface/depth limits stay explicit.

It does not close layer-equivalent adjustable scope (REQ-24), Adjustment Layer/node construction (REQ-25), external registry (REQ-68), extension parameter coverage across Preset/Macro/MCP (REQ-69), P06/R06 or L2.
