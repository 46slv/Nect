3. Align axis is `x` or `y`; geometric alignment is `min`, `center`, or `max`. `selection` with 2..1000 objects uses their union bounds, matching current behavior. `key_object:<id>` requires the key in selection, fixes it exactly and aligns the other 1..999 objects to that key's corresponding bound/center. `artboard:<id>` uses evaluated Artboard bounds; `grid:<id>` uses authored Grid bounds at evaluated Artboard origin and does not constrain placement outside the Grid; either permits 1..1000 selected objects. `guide:<id>` requires the Guide in the same Composition and matching axis; it aligns the requested min/center/max feature to the Guide coordinate, permitting 1..1000 objects. An x alignment to a y Guide or vice versa rejects explicitly. Desktop exposes reference type and selected key/Artboard/Grid/Guide identity before the command, with clear disabled/error states; keep quick align defaults compatible.
4. `alignment:"baseline"` is y-only. Use the actual first-line horizontal, axis-aligned text metric already exposed by C1; all selected objects must be eligible Text. `selection` targets the minimum first-line baseline in Composition y and keeps that source stationary; `key_object:<id>` targets the selected key Text baseline and fixes the key. Artboard/Grid/Guide baseline requests, rotated/vertical Text, and missing metric reject explicitly; glyph-box bottom is never a substitute. Subsequent-line and rotated/vertical residuals remain open.
5. Distribute axis is `x` or `y`, using sizes from evaluated bounds; no baseline distribution. `selection` with 3..1000 initially nonoverlapping objects sorts by starting minimum (stable ID tie), fixes both outer objects and equalizes gaps. `key_object:<id>` with 2..1000 initially nonoverlapping objects fixes the selected key and requires explicit finite `spacing >= 0` du. Retain starting order on each side and pack outward from the key with exactly that gap; omitted spacing must reject, with no inferred average. `artboard:<id>` or `grid:<id>` with 1..1000 objects uses the reference min/max as fixed virtual outer edges: gap `(span - sum(selected extents)) / (n+1)`, requiring nonnegative gap; place sorted objects from the near edge. A selected object may start outside the reference bounds, provided the resulting arrangement fits; do not reject merely for its initial outside position. `guide:<id>` always rejects `UNSUPPORTED_DISTRIBUTION_REFERENCE`.
6. Errors distinguish bad reference/axis/alignment, missing or invalid Grid, incompatible Guide axis, unsupported baseline/distribution, missing/negative spacing, initial overlap, cross-plane and preservation failure. UI/API should show the returned code and target, not silently substitute `selection`. Inspector/API/native after a successful edit must agree. History label names the reference and spacing where applicable. Editing inputs/draft alone does not issue a command; the Apply action uses current revision and current selection, and a stale draft rejects or refreshes visibly.
