# R09-D6 — complementary binary erosion

Status: Sol-frozen implementation packet, 2026-09-27. Baseline: clean synchronized `codex/practical-alpha@fa9baaa4319f9d599a03ded60477f3320e0a1557`. Authority: DEC-71, [Completion Route R09/P09](https://app.notion.com/p/3e3fd279a6f381b4ba9dd2d1bf066e0f) and Confirmed [REQ-66](https://app.notion.com/p/3e0fd279a6f38157bd50d72a2f48654b). R09-D5 provides cross dilation as the first derived mask. This packet adds one complementary unary primitive, not a general mask Boolean operation or whole REQ-66 closure.

## Contract

- Extend the existing read-only `analyze_regions` and formal `nect_analyze_regions` result with a top-level `erosion` object; keep R09-D1–D5 output fields, limits and refusal precedence unchanged. Derive from the same original thresholded, committed transparent Canvas Artboard output (`alpha >= threshold`), not from D5 dilation or prior erosion output. Reuse exact identity, expected revision, active-gesture, scale, threshold, 4,000,000-pixel and native/History guards. No authored mask, new renderer, Session command, file operation or native writer change.
- Use fixed cross kernel `{(0,0),(-1,0),(1,0),(0,-1),(0,1)}`. A destination pixel is foreground iff **all five** kernel positions are inside the output image and foreground in the original binary input. Outside is background, so the outermost image row and column always erode away. This operation is one pass with no feedback.
- Return `erosion` as `{operation:"erode", kernel:"cross-4-radius-1", border:"outside-background", coordinate_space:"artboard-output-pixels", area, runs}`. `runs` are maximal horizontal `{y,x,width}` spans of foreground output in row-major order. `area` equals summed run widths. The enclosing width, height, threshold, scale, source revision and alpha/pixel domain apply to both D5 and D6 masks. The result is a replaceable, lossless derived binary mask without persistent ID.
- Refuse the 20,001st erosion run with `ANALYSIS_LIMIT` and no partial API/MCP result. D1–D5 checks retain precedence. The result has at most 4,000,000 pixels. Success/refusal changes no Document, revision, History or native bytes.

## Independent oracles

1. A full 3×3 binary image erodes to only center `(1,1)`, area 1, run `{y:1,x:1,width:1}`. A full 5×5 image erodes to the central 3×3, area 9 and rows `{1,1,3}`, `{2,1,3}`, `{3,1,3}`. A zero image, an isolated source pixel and a 1-pixel horizontal or diagonal stroke each erode to empty output. Full 1×N and N×1 images are empty because their orthogonal neighbors lie outside.
2. A full 5×5 image with center `(2,2)` transparent erodes to exactly four isolated pixels `(1,1),(3,1),(1,3),(3,3)` (area 4; two width-1 runs on rows 1 and 3). A center alpha-127 hole remains background at threshold 128 but becomes foreground at 127, changing the result back to central 3×3. Verify D5 dilation from the same image still fills the hole, so D6 cannot consume D5 output.
3. Construct one connected full image with 6,700 isolated transparent holes on a 4-pixel grid inside its bounds. D1 region count stays 1; D2 edge runs, D3 boundary edges, D4 line candidates and D5 dilation runs remain below their caps. The erosion result exceeds 20,000 runs and the real API must return `ANALYSIS_LIMIT` without a partial result or authored-state change. Check direct pixel helper and real Canvas/API on small hand-computed cases and direct API/formal MCP nonempty erosion parity. Earlier stale identity/revision, gesture, unknown-field, threshold and output-size refusals remain exact.
