## Contract

- Extend the existing `analyze_regions` result and formal `nect_analyze_regions` MCP readback with `outer_contours`. Reuse the same committed transparent Canvas Artboard raster, identity/revision/gesture guards, alpha threshold, 4-connected foreground components, pixel/region/edge-run caps and errors. No new Session command, native format, authored Path or file operation.
- A contour is a closed polygon of **pixel-corner** vertices on the integer grid `[0,width] × [0,height]`, with top-left origin and implicit last-to-first closure (do not repeat the first vertex). Each directed boundary unit edge has foreground on its right in image coordinates. Trace every boundary edge of each 4-connected component exactly once; at a diagonal vertex crossing, take a right turn before straight or left, keeping corner-touching cycles separate. Clockwise image-coordinate cycles have positive signed shoelace area and are returned as outer contours. Counterclockwise inner cycles, including transparent-hole boundaries, are omitted. A single 4-connected component can yield more than one outer cycle if its boundary touches itself at a vertex.
- Each contour reports `region_index` (zero-based index in `regions`), `closed: true`, and `vertices` as integer `[x,y]` pairs. Remove only collinear intermediate grid vertices; retain every corner, including concave corners. Rotate each polygon to its minimum `(y,x)` vertex and sort contours by `region_index`, then start `(y,x)`, then vertex sequence. Report `contour_rule: "foreground-right-clockwise-outer"`, `contour_coordinate_space: "artboard-output-pixel-corners"` and `contour_closed: "implicit-last-to-first"`. Preserve existing region/edge coordinate metadata and source revision.
- Empty alpha output yields an empty array. Isolated pixels produce four corners. Artboard-edge shapes may use corner coordinates equal to width or height. Alpha equality is foreground. Reject if more than 200,000 directed boundary unit edges would be traced across all regions with `ANALYSIS_LIMIT` and no partial result. This is a separate cap from 100,000 edge runs. Count and refuse before publishing JSON. Do not silently simplify topology or truncate.

## Independent oracles

1. A filled 3×3 rectangle at pixels x=1..3, y=1..3 gives one contour with `[[1,1],[4,1],[4,4],[1,4]]`, region 0. A 1×1 pixel touching the bottom-right Artboard corner of a 3×3 output gives `[[2,2],[3,2],[3,3],[2,3]]`.
2. Two diagonal 1×1 pixels remain two regions and two independent four-vertex outer contours; a third 127-alpha pixel is excluded at threshold 128 and included at 127. A 5×5 opaque ring with a transparent center has one outer four-corner contour; its inner boundary is absent from `outer_contours`, while R09-D2 edge runs still include hole-adjacent foreground pixels.
3. A three-pixel L at `(1,1),(1,2),(2,2)` gives `[[1,1],[2,1],[2,2],[3,2],[3,3],[1,3]]`, retaining the concave corner. Use the pixel helper and real Canvas/API, then nonempty direct API/formal MCP parity. Verify unchanged native bytes, Document, revision and History. Existing invalid identity/revision/gesture/threshold and output-size refusals remain exact. Add a constructed boundary-length case that crosses the 200,000-edge cap while staying below the prior pixel, component and edge-run caps; assert no result is returned and no authored state changes.
