# R06-A — Offset Paths through the Effects panel

Status: Sol-frozen bounded implementation packet, 2026-09-27. Baseline: `codex/practical-alpha@cbac020644b6eddb51d455de80fa3c1378452720`. Authority: DEC-71, the [Completion Route](https://app.notion.com/p/3e3fd279a6f381b4ba9dd2d1bf066e0f) R06 entry, the [P06 packet](https://app.notion.com/p/3e3fd279a6f381ee8ab0ea5ea614c006), and Confirmed [REQ-22](https://app.notion.com/p/3e0fd279a6f3819e9833e6a914142ab8), [REQ-24](https://app.notion.com/p/3e0fd279a6f3816f89b4dcd41cb0abb6), [REQ-68](https://app.notion.com/p/3e0fd279a6f38145aa6be732b1ed863d), and [REQ-69](https://app.notion.com/p/3e0fd279a6f38164ac96c1f4cda26a5d). This is one built-in operator entry, not acceptance of those full Requirements.

## Selected operator and domain

- Use the existing real `nect.shape.offset` version 1 operation. Its instance has a stable ID and persisted behavior version. Its input and output are local path geometry on Path or Text objects, not composited pixels. The authored source remains editable; evaluation alone produces the offset contours. The existing `amount` and `miter_limit` Scalars, fill rule, line join, enabled state and ordered stack are authoritative.
- The first Effects catalog contains only this supported built-in entry. Search is case-insensitive and matches its visible name. Selection and Apply operate on the exact selected object in the current Session. A missing or unsupported target, invalid open/degenerate/self-intersecting path, unsupported parameter, or stale Session/revision must report the actual error and leave authored state, revision and Undo history unchanged. Do not substitute another effect or convert the source.
- Object-local Offset is the only accepted processing scope here. Group-after-children processing, adjustment scope, raster filter IO, unknown external operators, Presets and Macro Effects remain separate obligations. In particular, applying the same local Offset to each Group child is not Group processing.

## Effects panel route

- Add a dedicated discoverable Effects panel with a searchable built-in catalog, current target identity, and Apply. Apply must call the existing `AddOperation` Session path used by the Add menu/API. The panel must expose the applied Offset instance's normal parameter editing, reorder, bypass and remove route; it may reuse the current Inspector controls but must keep navigation explicit and usable from the Effects panel. No panel-only document state or fake preview.
- Preserve the existing Properties shape stack and Add menu behavior. The new entry should not obscure the difference between a geometry modifier and paint operations. After apply/edit/reorder/bypass/remove, read back the same authored instance through Session, API and native. Rebuild or retarget the panel on selection, document switch, Undo/Redo and external API edits; a stale panel action must not edit another object or document.
- Keep errors visible with target/type/reason. An empty search and unavailable target show clear nonmutating states. There is no promise of generic plugin discovery from this one catalog entry.

## Acceptance oracles

1. In the real Qt Window test host, create a retained closed Rectangle, search `offset`, apply from Effects, and read back `nect.shape.offset`, behavior version and stable instance ID from the Session. Edit Amount through its normal property control, reorder relative to another operation, bypass, remove, Undo/Redo, and confirm each action has the expected evaluation and one atomic revision. Compare an equivalent API `AddOperation` result with the same parameters by authored semantics and derived geometry, allowing separately allocated instance IDs.
2. Save the panel-authored document, cold decode/reopen it, and verify source geometry, operation ID, type/version, parameters, order and enabled state. SVG/Canvas must consume the same derived Offset; zero Amount and bypass preserve the defined input. Existing Offset geometry tests provide the independent numeric contour oracle.
3. Attempt Apply with no selection, Group/Image, and an open or invalid Path. Check exact visible refusal and unchanged encoded Document/revision/history. An unknown type/version must be explicitly rejected and must not be silently executed or coerced into Offset; unknown native passthrough is not part of this slice. A stale panel action after document or target change must refuse or retarget safely, never edit the old target by name or stack index.

## Residuals and evidence boundary

This packet does not close all of P06/R06, REQ-20–29/68/69/161, or L2. A single hardcoded built-in entry is not an extension registry. REQ-22 still requires custom Macro search/apply after P07. REQ-24 requires real Group/layer scope, with child processing before Group effect. Automated Qt interaction is code-path evidence; hands-on Windows usability stays `LOCAL_WAIT` until an owned controllable window is available. Preserve R05-C's separate hands-on `LOCAL_WAIT`.

## Implementation and review, 2026-09-27

The dedicated Effects dock searches the real built-in Offset, displays the exact selected target, applies it through the existing `AddOperation` Session route, and lists stable instance IDs. Each instance opens the normal Properties stack controls for Amount, Miter limit, order, bypass and removal; the View menu can reopen the dock. Selection, Session and revision guards prevent an old card from editing a new target. Errors display target, type and reason. No core, native or operator format change was needed.

Sol reviewed the code, the existing Offset/API/native contracts and the focused Qt interaction test. The test exercises search, no selection, Group and open-path refusal, real apply/edit/reorder/bypass/remove, Undo/Redo, stale target, API amount/derived geometry parity and native cold reopen. The existing core/process tests continue to cover strict unknown type/version refusal and the independent Offset contour oracle. The first full serial CTest run exposed a `window_interaction` fixture assumption: its comparison used a zoom computed before dock content could resize the Canvas. The test now computes `fit_artboard` and `fit_all_artboards` in the same viewport, preserving the active-composition assertion. A focused rebuild and test passed, then the Release build and serial CTest passed **42/42**. This is automated Qt/API/native evidence, not hands-on Windows usability or full P06 acceptance.
