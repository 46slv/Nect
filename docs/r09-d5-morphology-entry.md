## Contract

- Extend the existing read-only `analyze_regions` result and formal `nect_analyze_regions` readback with `morphology`. Derive its input from the **same** committed transparent Canvas Artboard output, where foreground means 8-bit output alpha byte `>= threshold`. Reuse exact Session/document identity, expected revision, active-gesture refusal, scale, threshold, source provenance and 4,000,000-pixel preflight. Existing D1–D4 fields, order, caps and refusal precedence remain unchanged. Do not add an authored mask, Session command, second renderer, file operation or native version.
- Apply one binary dilation with a fixed cross kernel `{(0,0),(-1,0),(1,0),(0,-1),(0,1)}`. A destination pixel is foreground iff its center or one in-bounds orthogonal neighbor was foreground in the **original** binary input; there is no iterative feedback. Outside the output image is background and the result is clipped to the Artboard output rectangle. Diagonal-only sources can join after dilation. This is pixel morphology, not path offset or alpha/luma mask authoring.
- Return `morphology` as `{operation:"dilate", kernel:"cross-4-radius-1", border:"outside-background-clipped", coordinate_space:"artboard-output-pixels", area, runs}`. `runs` is a row-major array of maximal horizontal `{y,x,width}` spans of output foreground pixels, with integer top-left pixel indexes and exclusive width. The run list plus image `width`/`height`, threshold, scale, source revision and pixel/alpha domain in the enclosing result is a lossless, structured binary input for a later boolean operation; it has no persistent ID. `area` is the sum of all run widths. Empty input yields area 0 and an empty run list. Full input stays full. No output is silently truncated.
- Refuse the 20,001st morphology run with `ANALYSIS_LIMIT` and no partial API/MCP result. The 20,000-run bound can be exercised while all D1–D4 caps remain satisfied. Earlier region, edge-run, boundary-edge and line-candidate limits retain their precedence. The mask cannot exceed the existing 4,000,000 output pixels. On success or refusal, native bytes, Document, revision and History are unchanged.

## Independent oracles

1. A single foreground pixel at `(2,2)` in a 5×5 output produces area 5 and runs `{y:1,x:2,width:1}`, `{y:2,x:1,width:3}`, `{y:3,x:2,width:1}`. A single pixel at `(0,0)` produces area 3 and runs `{0,0,2}`, `{1,0,1}`. A zero-alpha image gives no runs; a full 3×3 image gives three `{y,0,3}` runs and area 9.
2. Two diagonal source pixels `(1,1)` and `(2,2)` in a 4×4 output produce union runs `{0,1,1}`, `{1,0,3}`, `{2,1,3}`, `{3,2,1}` and area 8. At threshold 128, a 127-alpha isolated source is absent; at threshold 127 it dilates. A 5×5 opaque square with its center transparent fills that one-pixel hole after dilation; its output remains 5×5 full. The algorithm must read original input, so dilation never extends two steps from an isolated source.
3. Check the pixel helper against hand-computed runs and a real Canvas/API result; compare nonempty direct API and formal MCP results. For the run cap, use isolated sources spaced four pixels apart: 6,666 interior sources produce 19,998 morphology runs; one separated top-corner source contributes two clipped runs for exact 20,000 acceptance. Another separated interior source exceeds the cap, while source components, edge runs, boundary edges and line candidates remain below their earlier caps. Verify no partial result or authored-state change on refusal. Existing stale identity/revision, gesture, unknown field, invalid threshold and oversized output refusals remain exact.
