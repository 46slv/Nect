## Interaction and state contract

1. Draw x Guides as constant world X and y Guides as constant world Y across the active Composition viewport. Draw active Artboard Margin as its evaluated inset rectangle. Draw each visible Artboard Grid at evaluated Artboard origin plus its local bounds; show rectangle, row/column cell edges and gutter boundaries. Clip Grid to its own bounds. Draw on the Canvas after artwork without entering native, SVG or PNG export; selection and authored object geometry remain unchanged. Use legible low-noise strokes at 100% and 200% DPI. An empty document has no spurious overlay.
2. `show_guides`, `show_grid` and `show_margin` are independent per-window view booleans, default ON when their authored definitions exist. Toggling them changes no Document revision, Undo, recovery bytes or export. Existing Snap enable state remains independent; hiding an overlay must not disable any existing snap, and P02-C will add Guide/Grid candidate toggles and feedback. Do not display a Guide/Grid snap control as functional before P02-C supplies its behavior.
3. Existing active-frame settings expose Margin inset fields; Grid bounds/count/gutter fields; an explicit one-time **Set Grid to margin box** action; and a Composition Guide list with add/edit/delete, axis and position. Labels include du units and stable human-readable names. Numeric fields commit on Enter or explicit Apply; focus alone or a visible draft is not a commit. Clearing Margin preserves Grid; clearing Grid preserves Margin; clearing the last component sends null layout. Guide add uses `new_id()` and successful edit/delete retains or removes only its stable ID. Existing Grid edits retain its ID; first creation allocates one.
4. The copy action requires an authored Margin. It calculates `{left,top,width-left-right,height-top-bottom}` from the evaluated active Artboard and writes those four Artboard-local Grid bounds in one `SetArtboardLayout` command, preserving existing Grid counts/gutters/ID or creating an ID with valid first-slice counts 1×1 and zero gutters. It does not create a persistent link. A later Margin edit leaves Grid numbers unchanged. Without Margin, reject `INVALID_LAYOUT` visibly and leave revision/history/state unchanged.
5. A Guide position drag occurs only in explicit Guide edit mode so object/point drags keep their existing routing. Hit test is 6 logical px at any DPR; an exact-distance tie chooses lexicographic Guide ID. Start freezes Session/document identity, revision, Guide ID, axis, zoom and authored snapshot. Preview is transient through the same Session gesture; Escape cancels without revision/history. Release commits one Undo. If API/Undo/document switch advances identity or revision, reject stale commit, discard preview, refresh and require a new gesture. Invalid numeric/layout previews leave the last valid preview visible and do not commit.
6. Window editing uses `AddGuide`, `UpdateGuide`, `DeleteGuide` and a complete `SetArtboardLayout` payload through the existing Session/Host notification path. Validation errors are visible near the control or status, and failed edits restore the committed field display. Undo/Redo, save/reopen, recovery and API inspect read the same accepted definitions. Artboard resize that violates Margin/Grid is rejected atomically with no scale/clamp. Do not silently coerce a fractional count, negative gutter, nonfinite value, wrong plane, duplicate ID or stale revision.
