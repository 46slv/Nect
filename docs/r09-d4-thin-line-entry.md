# R09-D4 — exact thin-line candidates

Status: Sol-frozen bounded implementation packet, 2026-09-27. Baseline: clean synchronized `codex/practical-alpha@8596b3d1347e8e7af165d0529887ece9dfcf101f`; R09-D1/D2/D3 are prior read-only analysis results. Authority: DEC-71, [Completion Route R09/P09](https://app.notion.com/p/3e3fd279a6f381b4ba9dd2d1bf066e0f) and Confirmed [REQ-65](https://app.notion.com/p/3e0fd279a6f38154abe3d69aba50dc30). This is one deterministic pixel-line primitive, not a general Hough detector, vector centerline tracer or REQ-65 closure.

## Contract

- Extend `analyze_regions` and formal `nect_analyze_regions` readback with `line_candidates` computed from the same committed transparent Canvas Artboard output and alpha threshold. Preserve exact identity, expected revision, gesture refusal, coordinates/provenance, native/History immutability and prior region/edge/contour results and limits. No authored objects or persistent candidate IDs.
- A candidate is a maximal run of at least **three** threshold-foreground pixel centers in one of four unit-step directions: horizontal `(1,0)`, vertical `(0,1)`, descending diagonal `(1,1)`, ascending diagonal `(1,-1)` in top-left image coordinates. The run includes every consecutive qualifying pixel and cannot extend one pixel further in either direction. All four orientations are examined; intersections can produce separate candidates only where the thinness rule permits them.
- Thinness rule: a horizontal qualifying pixel has no foreground directly above or below; a vertical qualifying pixel has no foreground directly left or right. A diagonal qualifying pixel has no foreground in any of its four orthogonal neighbors. Outside-image neighbors count as background. This deliberately rejects thick fills/stripes and can break lines at junctions. It does not estimate subpixel position or join gaps.
- Return `{direction,start:[x,y],end:[x,y],length_pixels}` with integer pixel-center indexes and inclusive endpoints. `direction` is `horizontal`, `vertical`, `down_diagonal` or `up_diagonal`; direction order is as listed. Sort by direction order, then start `(y,x)`. Report `line_rule: "exact-one-pixel-wide-4-direction-min3"` and `line_coordinate_space: "artboard-output-pixel-centers"`. At most 10,000 candidates; the 10,001st refuses with `ANALYSIS_LIMIT` and no partial result. Keep the existing R09-D1/D2/D3 cap precedence and error behavior.

## Independent oracles

1. A 5-pixel horizontal stroke at y=1, x=1..5 yields exactly one horizontal candidate `(1,1)` to `(5,1)` of length 5. The same 5×2 filled stripe yields no candidate, as each pixel has a perpendicular foreground neighbor. A solid 3×3 rectangle yields none.
2. Three diagonal foreground pixels `(0,0),(1,1),(2,2)` are three separate 4-connected regions but yield one descending diagonal candidate of length 3. If the third pixel has alpha 127, threshold 128 yields no candidate and threshold 127 yields that candidate. An ascending diagonal `(0,2),(1,1),(2,0)` yields one ascending candidate. Artboard-border pixels still qualify when their outside neighbor is background.
3. A horizontal run interrupted by a perpendicular branch fails at the junction, so no length-3 candidate may bridge that disqualified pixel. An isolated two-pixel line is omitted. A constructed binary image must prove exact 10,000-candidate acceptance and 10,001st refusal while staying below pixel/component/edge-run/contour caps. Compare pixel helper, real Canvas/API and nonempty direct API/formal MCP parity, then verify unchanged native bytes, Document, revision and History on successful and refused reads.

## Residuals

This detects exact one-pixel center runs only. Antialiased/subpixel, arbitrary-angle, thick, gapped, curved, junction-aware, color-grouped and fitted lines remain separate work. It is read-only and does not adopt Path or mask candidates into authored state. REQ-65/66, R09/P09 and L2 remain open; R09-A mask design and hands-on GUI obligations stay local waits.
