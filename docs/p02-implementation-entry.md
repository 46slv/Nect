## Native 0.14 and identity contract

Current writer is `nect-native` 0.13, strict `additionalProperties:false`; `include/nect/io.hpp` declares `native_version="0.13"`, and `src/io.cpp` accepts 0.1–0.13. P02-A adds strict 0.14, updates the writer and decoder together, and keeps the exact existing root keys. Frozen target structure (all fields named here are contract fields, not current code):

```text
Composition.guides = [{id, name, axis: "x"|"y", position}]   // 0.14 required array, may be []
Artboard.layout? = {
  margin?: {left, top, right, bottom},
  grid?: {id, bounds: {x, y, width, height},
          columns, rows, column_gutter, row_gutter}
}
```

`du96` is the native unit, Y grows downward, and Composition owns the plane. A Guide with axis `x` is a vertical constant-X line; `y` is horizontal. Its `position` is in its Composition's plane, independent of an Artboard; its opaque ID is document-unique. A Grid has a document-unique opaque ID, one optional Grid per Artboard layout; its bounds are Artboard-local, so its world rectangle is evaluated Artboard origin plus local bounds. Margin insets have no separate ID and are addressed by stable Artboard ID. `layout` may contain either or both definitions; clearing one preserves the other. Renames, reorder, moves, save/reopen, recovery and Undo preserve surviving IDs. Delete removes an ID; re-add creates a new one. Artboard duplication allocates a new Grid ID; deletion removes that Artboard's layout. No Guide is implicitly copied with an Artboard.

Margin and Grid bounds are independent authored values. `Set Grid to margin box` requires an authored Margin; it calculates `(left, top, artboard.width-left-right, artboard.height-top-bottom)` from the current evaluated Artboard and writes those four local Grid numbers once. Without Margin it rejects `INVALID_LAYOUT`; later margin edits do not relink or move Grid. Artboard translation carries its Grid's world position, but leaves the local numbers unchanged. Resizing, including a parent-size evaluation change, must revalidate the unchanged local layout against the new evaluated size and reject atomically if invalid. It never clamps or scales definitions; a separately specified compound edit can change size and layout together.

Validation at schema and core: all numbers finite; Guide `abs(position) <= 1e9` du and at most 10,000 Guides document-wide (`LIMIT`; schema also caps each Composition array at 10,000); Artboard existing positive width/height <= 1e7 and position magnitude <= 1e9 still apply. Each present margin is nonnegative with `left+right < evaluated_width` and `top+bottom < evaluated_height`. Grid `x,y >= 0`, `width,height > 0`, `x+width <= evaluated_width`, `y+height <= evaluated_height`; counts are integers 1..1000; gutters are nonnegative; cell widths `(width-(columns-1)*column_gutter)/columns > 0` and heights analogously. Use exact double validation without silent tolerance-based repair. IDs must be nonempty and unique across existing document-owned IDs; reject duplicate, missing and wrong-plane references. The Guide resource cap is a revision-4 P02-A engineering clarification; these limits are not Notion product requirement thresholds.

0.1–0.13 load migration supplies `guides=[]` and absent `layout` while preserving all existing IDs, geometry and authored values. Saving from the new writer emits 0.14; load → edit → save → fresh reopen must reproduce definitions and stable IDs. A 0.13 reader must reject unknown 0.14 as `UNSUPPORTED_FORMAT` and leave source bytes untouched. A 0.14 reader rejects unknown future versions and unknown fields. SVG/PNG exports contain artwork, not Guide/Grid/Margin overlays; saving native keeps all authored definitions. Native reader, recovery, API inspect and Desktop must agree on the same committed state.

Both components may change in one command only when explicitly supplied as a compound edit.
- The `apply` envelope carries exact document/session identity and `expected_revision`, as in current API/Host. Existing `REVISION_CONFLICT` rejects stale requests. The P02-A commands use `MISSING_COMPOSITION`, `MISSING_ARTBOARD`, `MISSING_GUIDE`, `DUPLICATE_ID`, `WRONG_COMPOSITION`, `INVALID_GUIDE`, `INVALID_LAYOUT` as stable failure families. `MISSING_GRID` is reserved for a future targeted Grid-by-ID edit; the complete-layout setter does not look up a prior Grid ID. Existing `INVALID_BATCH`, `HISTORY_LIMIT` and malformed-command errors remain. Never coerce unknown axes, missing IDs, invalid values or future native versions to defaults. A batch validates the entire candidate before commit; any failure keeps document, revision, history cursor and redo branch unchanged.
- A Guide/setting drag begins from one Session revision and a frozen snapshot. Preview is transient, Escape cancels with no new revision/history, and one accepted gesture produces one Undo. A concurrent API edit or document/session switch makes its commit stale: reject, discard preview, refresh and ask for a new gesture; no blind rebase or resend. Undo/Redo restores exact definitions and IDs. History equality and retained-byte accounting include Composition guides and Artboard layout. A history-admission failure leaves the prior document/timeline intact.
- Recovery persists only the accepted Session revision and native 0.14 definitions. Reopen/cold restart compares native, recovery and read-only API identities/values; canceled, failed or stale drafts never appear. Desktop toggles described below are view state and cause no document revision. No separate recovery copy of editable layout is authoritative.

## Snap and layout command behavior

Gesture start freezes moving stable IDs, target IDs and geometry, active Composition, entered Group scope, zoom and start revision. Candidate X and Y corrections are evaluated independently in **logical screen pixels**; `abs(correction) <= 6` qualifies, independent of DPR. Use the smallest absolute correction first. Exact ties resolve by type Guide > Grid > Artboard > Text baseline > object edge > object center > equal-gap, then lexicographic stable target ID, then fixed source-feature order (min, center, max; for Grid, ascending line coordinate). Simultaneous X/Y winners may both apply. Feedback names both target and feature. Candidate geometry and choice are deterministic; no epsilon changes a non-tie into a tie.

Guide/Grid overlay visibility and each snap enable toggle are independent per-window view settings. A hidden overlay whose snap toggle remains ON still qualifies and its transient snap feedback names it. A visible overlay with snap OFF does not qualify. Hidden objects never serve as object targets. A nonexistent authored lock model is not simulated. A definition edit does not move or clip artwork; objects may live outside Grid. Exact numeric/API edits and keyboard nudges do not snap. No momentary modifier override is required in this slice.

Grid candidate lines come from explicit rectangle boundaries, column/row cell edges and centers, including gutter boundaries; stable feature order is ascending coordinate, then boundary-before-center. Object candidates use existing evaluated geometric bounds and same-Composition/entered-Group scope. First-slice Text baseline comes from the actual first-line text metric transformed to Composition space, only for horizontal axis-aligned text; a multiline text source may offer its first line but no subsequent lines. Rotated or vertical text offers no baseline candidate in this slice; glyph bounds bottom is never a substitute. REQ-33 residual remains open. For a two-sided equal-gap candidate with left neighbor right edge `L1`, right neighbor left edge `R0`, moving width `w`, candidate left is `(L1+R0-w)/2`; offer only if resulting gaps are nonnegative and all objects share the Composition. One-sided repeated-gap candidates need their own exact fixture before implementation.

Object-body snap commits world displacement through the shared `TranslateObjects` solver, including one object. Point snap converts world target through the object's invertible start world-to-local transform and edits only selected stable point IDs (using existing Point Edit ownership for generated points). Driven selected axes, singular inverse, cross-Composition or structurally overlapping Group/child selection reject without changing any other point/object/source geometry. Failed preview never enters history.

`align_objects` accepts a single explicit `reference` variant: `selection`, `key_object:<id>`, `artboard:<id>`, `grid:<id>`, or `guide:<id>`; axis is x/y, alignment is min/center/max or the bounded text-baseline mode. The legacy JSON `artboard` field remains a compatibility alias; exactly one reference form may be supplied. A key ID must be selected and remains fixed, visibly named in the UI. Guide permits alignment on its matching axis only; Grid uses its explicit bounds; Artboard uses its evaluated bounds. Baseline align is y-axis, actual horizontal first-line text metric, selection/key text reference only in this slice. Any unsupported baseline/reference combination rejects explicitly, never aligns to a glyph box.

`distribute_objects` uses evaluated geometric bounds and explicit `reference`; no persistent constraint is authored. For `selection`, 3..1000 unique nonoverlapping objects sorted by starting minimum (stable ID tie) keep both outer objects fixed and equalize *gaps*, preserving current behavior. For `key_object:<id>`, 2..1000 objects include the fixed key and require an explicit finite `spacing >= 0` du; sort objects by starting minimum, retain order on each side of key, pack each side outward with that exact gap. Omitted spacing and inferred initial average gap reject. For `artboard:<id>` or `grid:<id>`, 1..1000 objects are sorted the same way; the two bounds are fixed virtual outer edges. Let `span` be reference width/height and `sizes` the selected extents; gap is `(span-sum(sizes))/(n+1)`, requiring gap >= 0. Guide distribution always rejects `UNSUPPORTED_DISTRIBUTION_REFERENCE`. Distribution uses bounds, not a baseline spacing mode. Invalid axis/reference, negative space, initial overlaps where selection/key ordering would be ambiguous, cross-Composition, duplicate/unknown targets, driven transforms and failed geometry preservation reject the full edit with no revision or Undo. One successful action is one Undo.
