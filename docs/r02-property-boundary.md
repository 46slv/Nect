Fix `resolve_name` so a unique named color and field `color` return its typed aggregate Color `Ref`, validated by the existing `color_channels` path. Keep the current Scalar channel lookup and its errors. Do not change the native schema, evaluator, Color commands or product color semantics. This closes one actual type discovery gap in the already accepted Color workflow; it does **not** claim all P03 types or generic Color expressions.

Positive oracle: create named colors with unique names and channel values; resolve the aggregate by name through the core API, read it with `get`, link it to a paint color via the existing typed `link_color` command, change the source, and check the target values, Undo, and `encode`/`decode` cold roundtrip. Negative oracles: unknown name, duplicate name, invalid Color field/owner, and a scalar-only `resolve_name` request still produce scoped errors; none commits a partial mutation.
