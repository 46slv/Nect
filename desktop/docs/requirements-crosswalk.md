# Nect legacy → Desktop requirements crosswalk (bounded first pass)

## Bottom line

The available evidence does **not** support saying that all old Nect requirements were carried over. The 2026-10-16 Desktop Brief selects a practical offline Windows editor and a named set of Musts, while explicitly preserving the C++/Qt Mission and keeping the legacy and Desktop formats distinct. The legacy product-direction document also cautions that its accepted direction does not pull the whole roadmap into a milestone. This is a bounded traceability pass over major requirement areas, not a full audit of every Notion requirement or every implementation/test.

The actual requirement database/leaf pages were not mapped in this pass. The product-home's redesign note is marked `unverified` and records open questions. Treat these as version-scoped evidence; update/reconcile the status summary before claiming current-WIP native completion.
4. **Gradients:** product-spec sections conflict as noted above; no single status should be inferred without fresh code/test readback.

The Brief summary is available in `CURRENT_GOAL.md`; original documents were not independently reviewed here.
6. **No all-tests audit:** this pass did not run tests or inspect every feature/test. It crosswalks documented requirements/status only. Current WIP validation boundaries come from `CURRENT_GOAL.md` and do not amount to an implementation review.

### P0 — representative end-to-end acceptance target

The user-selected production target is one complete, re-editable identity-design task: create a mark with holes and live mixed Japanese/Latin text; refine curves and character spacing; make purpose-specific variants on the supported output frames; export SVG and raster; save the editable Nect project, restart, reopen, then edit the text and the original Boolean source again. Run the same supported semantic edits once through ordinary UI controls and once through the AI/machine-facing command surface. Their authored state and one-step Undo/Redo results must agree. Undo must restore the previous state without flattening the original mark or converting the live text to outlines.

Use the supported Desktop model and formats for this acceptance target: editable JSON remains the Nect project authority; SVG/PNG are output artifacts. Purpose-specific variants can use the current Artboard workflow. This target does not adopt independently sized Compositions, broaden SVG import, promise AI/PSD compatibility, or require a Symbols/linked-instance feature. A Japanese short-heading fixture with mixed Latin text, punctuation/parentheses, and a tate-chu-yoko case is a proposed coverage fixture for the already adopted Japanese/English text scope; its exact supported shaping rules must be made explicit before treating it as a release gate.

**Acceptance status:** adopted as the next representative P0 workflow by the user's instruction. **Implementation status:** the component capabilities are described in Desktop scope and migration records, with some shared command families already present. **Verification status:** the task-wide restart/re-edit, UI-versus-machine parity, mixed Japanese/Latin fixture, source-preserving Boolean Undo, and export checks have not been run as a single current-build scenario. Prior focused suite/build evidence is version-scoped and does not substitute for this acceptance run.

## Traceability conclusion

For planning, treat the current Desktop Must list plus the explicitly adopted P0 goals above as the acceptance scope; trace individual legacy requirements into it only when the Brief or a current decision explicitly does so. Keep “legacy feature exists,” “similar feature exists in Desktop,” “format compatible,” and “same semantics verified” as separate claims. The present evidence supports selective adoption and deliberate exclusions, but **not full carryover or full Illustrator-replacement completion**.
