# Retained Path Remap fingerprint compatibility

## Contract

The expression-reference provenance change in
44e8010346f1d9e6612e1d18ce8895cda5b5f2ec inserted an empty array into
otherwise unchanged recursive hashes, without a schema change. Geometry and
stable point IDs did not change, but historical saved point edits were suspended.
Simply reverting the hash would instead suspend edits saved by the newer recipe.

The evaluator now produces the historical canonical identity for unchanged
default or reference-free-expression provenance and privately derives the exact empty-expression-field-era
identity from the same evaluated geometry. Both recipes include recursive source
identities and the same operator/source-fingerprint inputs. Convert to Path and
compound painted-value hashes participate too. No second geometry evaluation,
geometry-only matching, wildcard, authored alias or implicit rebinding is used.

Retained-edit rendering, nudge and drag admission, and Inspector suspension
feedback use the same predicate. Compatibility identities are private WeakMap
metadata. Evaluator-owned clone/cache/Transform/painted-group paths explicitly
preserve that metadata; plain caller clones and alias properties do not. Future
changes that clone evaluated paths must preserve this distinction. Serialization
is unchanged: stored fingerprints and authored deltas remain intact. Document
schema versions do not select a fingerprint era. Numeric expressions without
references have only deterministic arithmetic/functions, constants and the authored
base value; there is no clock, randomness or external lookup. Base values and
effective color/geometry/settings remain in the existing evaluation/hash inputs.

The focused fixtures bind the historical source revision
7effac3ce6ef36689766dda04aab426628fa2b56 and newer source revision
c865854ab4c8486c762303b4cb1d254657dcef74. The four saved JSON fixtures were
serialized by those original sources. The independent era identities are captured
from those sources, not generated by the compatibility implementation. Existing
luminance golden files are unchanged.

## Separate existing limitation

This repair does not introduce a new identity version or claim complete
transitive expression-parameter provenance. Both original and repaired evaluators
record a direct expression reference target, but do not recursively record the
referenced parameter's own source wiring.

Minimal reproduction:

1. Set Halftone pitch to ref("controller", "value").
2. Connect controller.value to Value A = 8; create Value B = 8.
3. Add Halftone → Convert to Path → Path Remap and a retained [+3,+5] edit.
4. Rewire controller.value from A to B.
5. Both geometry and the old hash remain unchanged, so the edit remains active.

Run `node tests/repros/remap-transitive-expression-rewire.mjs` from desktop to
observe this separate issue. It is a reproduction, not a passing acceptance
assertion or a relaxation of the direct-reference/source-rewiring regression
checks. Fixing it needs a separately designed identity-version/migration contract.

The original painted Convert to Path recipe also identifies its geometry, point
IDs and provenance, not every upstream literal setting. A tone change that leaves
an Ordered Dither image's thresholded geometry exactly unchanged can therefore
retain its edit in both original eras. This repair preserves that contract;
geometry-changing tone negative controls use a mid-gray image so the intended
invalidation is observable. It does not introduce settings-only invalidation.

## Verification boundary

The compatibility tests cover actual saved JSON from both eras; five luminance
families with vector and embedded-image inputs; continued nudge, typed editing,
drag preview/commit, Undo/Redo and repeated save/reload; mixed-era/chained Remaps;
clone/cache/Transform/bypass/zero and nonzero Offset/Set Closure; nested Composition
appearance; and real control changes, equal-geometry ordinary source rewiring,
direct expression-reference changes, missing points and arbitrary alias rejection.
Synthetic DOM checks cover the Inspector and canvas drag admission, not native
WebView2 display or Windows application acceptance. Production builds and focused
model checks are separate from the broad test-suite/native verification stages.
