# Parameter references in expressions

Numeric expressions now accept a bounded `ref` function:

- Scalar: `ref("node-id", "radius") * 0.5 + 10`
- Vector component: `ref("node-id", "center", "x") + 20`
- Vector2 destination: `ref("node-id", "center", "x"); ref("node-id", "center", "y") + 40`
- Curve handle length: `ref("curve-id", "point-id.handleA", "length")`

The searchable expression picker inserts stable IDs and numeric node-parameter keys. Labels remain human-readable. Renaming does not break references. X/Y are required for ordinary Vector2 sources; whole vectors, remap-point descriptors and geometry are not numeric expression operands. Color inputs have a separate typed slice described in [Color value and references](color-value-expressions.md). Within the current Artwork, the picker omits current/downstream nodes. Other Artwork candidates are omitted when they depend on the property being edited.

Within the same outer Composition, a numeric parameter can also read another Artwork with `ref(artwork, "layer-id", "node-id", "key")`; Vector2 and Curve-point sources add `"x"`, `"y"` or, for handles, `"length"`. Color expressions can use these numeric references as Scalar operation arguments. The source is the effective property value, including its connection or expression; another Artwork's unrelated output is not needed for the read. Qualified references require Document schema 62 and Composition wrapper version 2. A deleted source remains a diagnosed missing reference and Undo restores it. Older opaque wrapper expressions are retained, and imports or promotion that would give them a new interpretation are refused.

A Scalar expression may read a Scalar property in another outer Composition in the same project using `ref(composition, "composition-id", "artwork-id", "node-id", "key")`. The same operand is available in Scalar arguments of Color operations. Vector components, Curve points and handles, Color sources, and cross-file references are not supported by this form. The source is resolved in its own Composition, including its local and Artwork dependencies. Connections pause the destination expression; disconnecting validates the resumed value. Project-wide cycle and affected-value checks run before commit, including consumers in inactive Compositions. Missing sources stay diagnosed and Undo restores them; newly created identities cannot revive a previously missing target accidentally.

The form requires Document schema 63 and Composition wrapper version 2. Earlier readers reject an honest schema 63 project. A wrapper with an older, falsified version may preserve the text as opaque; old opaque text, including connected or otherwise unsupported descriptors, cannot be silently promoted to 63. Native JSON retains the authored text. Importing Compositions containing this reference, node Copy/Paste or Duplicate of it, Artwork Duplicate, and detached presets refuse explicitly until their identity and dependency contracts support it. Existing schema 62 Artwork behavior is unchanged.

`expressionReferenceTargetsForProject(project, compositionId, layerId, nodeId, type, targetKey)` adds eligible other-Composition Scalar candidates with stable owner IDs and complete expression text. `CompositionSessionOwner` binds each returned Document view or preview to its exact project snapshot for evaluation without serializing project data into the Document. `cloneDocument` retains that scoped context; arbitrary JSON/structured clones do not. `inheritProjectDocumentContext` is for an explicit derived Document projection of the same snapshot. A detached Document without its project reports a missing project context rather than resolving against another project.

Document schema 64 adds typed Color sources in the same project: `ref(colorArtwork, "layer-id", "node-id", "key")` addresses a different Artwork in the current Composition, and `ref(colorComposition, "composition-id", "layer-id", "node-id", "key")` addresses a different outer Composition. The destination is a Color expression or the Color argument of an existing Color operation. Numeric `artwork` references yield a Scalar, including when projecting a Vector2 component; numeric `composition` references address Scalar properties. Direct Color references retain the exact source `{hex, alpha}`, including hidden RGB when alpha is zero; a source may itself be connected, expressed, bound to a shared Color, or use the legacy Fill fallback. Following a Color property does not create a shared Color binding or palette attribution at the destination.

The picker returns these typed expressions alongside same-Artwork Color candidates, with stable source IDs and cycle exclusion. Color and numeric dependencies share candidate validation, connection precedence, missing-source diagnostics, Undo/Redo, and project-scoped snapshot evaluation. Import, Copy/Paste, Duplicate and detached presets with qualified Color references refuse explicitly until safe remapping is available. Old wrapper expressions containing the new syntax remain opaque through schema 63; promotion or import cannot silently activate them. Earlier readers reject honest schema 64 projects.

Document schema 65 adds `ref(componentComposition, "composition-id", "artwork-id", "node-id", "key", "x")` for an effective Vector2 component in another outer Composition. `"y"` is also available; Curve point keys `point-id.position`, `point-id.handleA`, and `point-id.handleB` retain their stable point IDs, and handle keys additionally accept `"length"`. Each reference yields a Scalar and can appear in Scalar expressions, either side of a semicolon-separated Vector2 expression, or Scalar arguments of Color operations. It reads the source-local property before any downstream Transform; no coordinate conversion is implied. The source must be in another outer Composition of the same project.

The project picker includes eligible component candidates for Scalar and Vector2 destinations, with full insertion text and cycle exclusion. Connections pause expressions; project-wide cycle and effective-value validation include inactive consumers. Missing source nodes or points stay diagnosed, Undo restores them, and identity reuse cannot silently retarget a missing reference. Import, Copy/Paste, Duplicate and detached presets containing this form refuse until their remapping contract is implemented. Earlier readers reject honest schema 65 projects; old wrappers may retain even malformed reserved-prefix text as opaque and promotion or transfer cannot activate it. Unrelated transfers do not require schema 65.

Multi-Artwork Duplicate in place remaps numeric Artwork references between the selected copies and refuses an unselected external source. Imports include referenced Artwork layers and remap their owned identities. Nodes with numeric Artwork references can be copied and pasted within their original Artwork while their source identities remain present; a missing or replaced source requires a fresh Copy. Pasting such nodes into another Artwork and storing them as detached node presets are currently refused; existing local-reference behavior is unchanged.

Curve point references use stable point IDs. `point-id.position` exposes `x` and `y`; incoming `point-id.handleA` and outgoing `point-id.handleB` expose `x`, `y`, and `length`. Handle components are relative vectors, and length is `Math.hypot` of the effective vector after connections and expressions. Apply, Color scalar preview, and live evaluation use the same projection and reject non-finite results. A missing or deleted owner/point stays authored and is diagnosed; Undo restores the prior target. References to sibling properties of the same Curve remain excluded by the existing node-level cycle rule.

An applied handle reference requires Document schema 61; point-position references continue to require 60. The `length` component is allowed only with a handle key and requires schema 61 even if the owner is missing. Wrapped projects use `compositionSchemaVersion: 2` for both 60 and 61. Older dangling handle-shaped `x`/`y` references and two-argument Color references retain their prior meaning. Clipboard and import remap an embedded point ID only for a matching copied Curve and point, preserving the handle field and projection. Schema versions do not downgrade on clearing, except through Undo.

References read effective values, including expressions and connected inputs. A destination's connected socket still takes precedence over its expression. Existing arithmetic, constants, functions, and semicolon-separated Vector2 expressions remain available. This is an extension of the existing parser, not JavaScript: arbitrary code, object/property access, and dynamic evaluation are not supported. The 4096-character expression limit, finite-value checks, graph-depth limits, locks, and history transactions remain enforced.

Changes to referenced values invalidate numeric dependencies, including Text's independent Position output, without requiring Text outline generation. Group duplication remaps copied node references; individual copies keep external references. Deleting a source retains an explicit missing-reference diagnostic, so Undo or restoration can recover it. Saved expressions use the existing parameter-expression field; no new graph node or data container is introduced.

Group remapping preserves authored whitespace, including spaces, tabs and newlines between `ref` and `(`. Every internal occurrence is remapped, including both `X; Y` parts and dormant expressions under connected sockets; external and dangling IDs remain unchanged. The bounded remap matcher follows the current restricted quoted-ID grammar, not arbitrary strings or escapes. This whitespace correction did not itself add syntax or a schema version; the handle reference extension above does. Regression check: `node --test tests/parameter-reference-expressions.test.js`.

## UI integration

`expressionReferenceTargetsForDocument(document, layerId, nodeId, type, targetKey)` returns local and eligible other-Artwork choices with their stable owner IDs and ready-to-insert expressions. The target key permits a different property of the destination node to participate without creating a false cycle; the existing same-Artwork exclusion remains. The editor names the source Artwork and distinguishes matching names by ID. Long names remain searchable in full and are available on the visible option. Pen drafts use the existing local `expressionReferenceTargets` until they become authored Artwork. Apply with the existing `set-parameter-expression` command. Effective results remain read-only. Scalar and Vector2 inputs expose separate authored Base controls while driven; these use `set-parameter-base`, not the ordinary `set-parameter` command.

## Related interaction corrections

- Splitting Transform scale materializes the current evaluated X scale before Y can change; existing linked/locked Y descriptors remain intact.
- `delete-nodes` accepts `nodeIds`, preserves Output nodes, disconnects surviving input sockets, and commits once. Returned `deletedNodeIds` and `retainedNodeIds` support a clear UI notice. Existing Reference and expression targets remain explicitly dangling.
- Curve/Path Remap `position` gestures accept `pointIds` containing the primary `pointId`. Every anchor receives the same delta in one transaction. Relative handles stay unchanged. Missing, locked, or driven anchors reject the whole group.

## Inline predictive completion

In the ƒ expression dialog, type the beginning of a function, node name (or a word in its name), or numeric parameter key. Up/Down selects a suggestion; Enter or Tab inserts it. A function inserts parentheses and puts the caret inside. Parameter suggestions insert the same stable-ID `ref(...)` syntax as the searchable reference picker, with Scalar, Vector2 X/Y, or Curve handle Length labels and the source node ID to distinguish duplicate names. Typing `ref` also lists eligible references. Only the first 12 matching choices appear; type a longer prefix or use “Insert parameter reference…” for broader searching.

Suggestions use the actual arithmetic grammar: `sin`, `cos`, `tan`, `abs`, `sqrt`, `min`, `max`, `round`, `pi`, `e`, and `value`. They do not add JavaScript, property access, time variables, or whole-vector operands. A Vector2 destination still uses separate `X; Y` scalar expressions. Targets are resolved from the current composition when suggesting and again before insertion, excluding self/downstream nodes.

Completion only edits the draft. Apply (or Enter with no active suggestion) commits through the existing command and Undo history; Cancel leaves the document untouched. Escape first dismisses suggestions, then closes the dialog. Shift+Tab and Tab without suggestions retain normal focus navigation. Suggestions stay hidden inside quoted strings, for selected text, and during IME composition. The original searchable insertion button remains available.

Focused checks: `node --test tests/expression-completion.test.js tests/expression-completion-dom.test.js tests/parameter-reference-expressions.test.js`.

## Authored base expressions (schema 26)

`value` reads the input's saved `q.value`, before its expression. It never reads the previous evaluation result, adds a dependency edge, or accumulates across reevaluation. Numeric expression examples:

- Scalar: `value + 10`
- XY: `ref("neighbor-id", "position", "x") + value; ref("neighbor-id", "position", "y") + value`

XY remains two scalar expressions separated by `;`: the left `value` is Base X and the right `value` is Base Y. With neighbor `[100,200]` and base `[20,10]`, the result is `[120,210]`; changing Base X to 30 gives `[130,210]` without adding a node. IDs must come from a real numeric reference target. This is not whole-vector arithmetic: `ref("neighbor-id", "position") + value`, `value + 10` on XY, Color arithmetic, arbitrary JavaScript, `input`, and automatic broadcasting remain unsupported. Effective self-references via `ref` still reject as cycles.

Driven numeric fields show Base controls, a read-only Result, and collapsible saved Expression. Base edits and horizontal scrubs use the dedicated core `set-parameter-base` command (payload: `layerId`, `nodeId`, `key`, numeric `value`, optional XY `axis`). Enter applies typed Base, Escape restores the typed draft; dragging commits once and Escape cancels the gesture. Parameter/composition locks, finite/type/domain checks, revision protection and atomic history still apply. Ordinary effective/canvas control edits retain their driven guard. Transform scale Base is displayed in percent while `value` uses its stored multiplier (50% means `value = 0.5`).

The precedence is unchanged: source connection > expression > base. Connected fields explicitly label their result and paused expression. Base editing while connected updates only the saved base; it does not change the source or the connected result. Disconnect restores the retained expression (if any), which may or may not use the saved base. Missing references show “Cannot evaluate”; no saved base or last-good value is displayed as a successful result. Invalid active expression results reject a base edit atomically.

The `va` completion offers `value` first and labels Scalar or the current X/Y component. Existing IME, quoted-string suppression, stale-target revalidation and 12-result limit remain intact.

No new parameter field is stored. Applying a bare `value` expression promotes the document to schemaVersion 26, including a dormant expression under a connection. Existing schema 24/25 documents without the new syntax retain their version; quoted `"value"` parameter keys do not trigger promotion. Importing bare `value` under a pre-26 version rejects rather than silently changing old semantics. Earlier readers reject version 26 as unsupported. Clearing an expression does not automatically downgrade a document.

This is the numeric/component slice, not all-input support. Whole-XY operands, Boolean/text expressions, typed-reference chips, dependency navigation/repair and the full design mock remain later work. Synthetic DOM verification is not real-browser rendering or desktop acceptance.

## Typed Color expressions (schema 42)

Color inputs, including Linear/Radial Gradient stop colors, accept `value` and `ref("node-id", "color-key")`. Their existing saved `{hex, alpha}` base stays editable beside the expression and read-only result. Color references use the same composition-local stable IDs and reference picker, filtered to Color properties. Numeric operands cannot read Color values. There is no Color arithmetic or palette storage in this slice. See [the scoped contract and verification](color-value-expressions.md).
