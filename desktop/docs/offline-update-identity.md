# Offline build identity and metadata validation

This slice adds one read-only native `query_build_identity` command, pure validators and a compact Build menu in the existing header. Production has a module-private constant `provider = null`. Opening Build queries native identity once, on demand; the cached query has no timer, update transport, settings or fixture activation path.

The native command accepts no renderer authority or identity arguments. Native startup constructs its immutable state after `RunStorage::prepare` succeeds. Build flavor follows the compiled Recovery feature, asset mode follows the compiled native protocol, and isolation follows the prepared storage value. An ordinary build in isolated storage remains isolated. The existing invalid-root, test-without-isolation and frontend/native profile refusals remain in place.

Identity integrity means local consistency, never signing or installation trust. Cargo supplies the version. The effective native context must retain that version and `com.nect.svg`; a mismatch produces `integrity = invalid` without a new startup failure. The exact Rust `TARGET` is embedded. Commit/build ID remain null, channel remains null with unknown authority, and package kind/authority remain unknown. Neither branch names, version 0.1.0 nor NSIS configuration imply a channel or installed package.

Both Vite and native build validation require exact Cargo/npm/base-Tauri/effective-Tauri version equality. JSON platform overlays and the final `TAURI_CONFIG` merge participate. Invalid JSON, invalid version values and drift fail the build. The currently enabled Tauri configuration format is JSON; no new format feature is enabled. The acceptance frontendDist-only overlay remains valid. Vite generates the frontend version and a static version marker from the checked Cargo source; static native builds also refuse stale frontend version markers. Existing profile markers remain separate.

`assessIdentity`, `validateDiscovery` and `validateVersionSet` are pure and do not mutate input. SemVer is complete ASCII SemVer 2.0 with a 128-character bound; decimal-string comparison preserves arbitrary integer precision. Build metadata and commit/build provenance never order versions. Only exact target `x86_64-pc-windows-msvc` and exact stable/preview channel values can qualify for fixture metadata assessment. Current production identity cannot qualify because its channel is unknown.

The discovery validator accepts a test-only provider descriptor and a seven-field request audience. Its closed response schema is `schema: 1`, all seven matching request fields, and either `kind: no-update` without a candidate or `kind: candidate` with required version/notes and optional buildId. Local transport failure is represented by the separate exact object `{ kind: 'transport-error' }`. Null provider wins before any identity, request or response inspection. Scope mismatches never become a negative result. Unknown values never establish an audience.

Only a strictly newer scoped candidate returns advisory version, literal notes and optional untrusted build label. Notes and labels are UTF-8 byte bounded and reject controls other than tab/LF/CR. UI text uses `textContent`; no HTML, Markdown or automatic links are created. Wording is source-qualified: “Update checks not configured”, “No update reported by this source”, and “Newer version reported by source”. There are no apply controls.
