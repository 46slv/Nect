# Workspace surface registration

`WORKSPACE_SURFACES` is the static declaration of existing drawer controls. The workspace controller validates the full declaration and trusted adapter mapping before touching DOM or preferences. `main.js` composes the existing owners into those adapters; the controller remains view-only and does not write the document or history.

The Assets adapter keeps the existing singleton under `document.body` and aligns it to the drawer's fixed slot. Drawer close, panel switch, viewer suspension and drag retreat hide or suspend that same element; they do not dispose the Assets owner. The Assets owner's own Close/Escape keeps its existing disposal and epoch behavior. Existing Shared Colors and selector-based panels remain legacy bindings, including their existing event and Session ownership.

The Colors binding mounts its view after the Assets slot and synchronizes its visibility; it can still attach an existing element for legacy callers. The Alignment binding synchronizes its toolbar pressed state. Adapter refresh runs in reverse declaration order so these updates precede the Assets slot measurement. This preserves the existing order; it is not a general layout policy.

Production supplies the Shared Colors controller's view factory to its fixed adapter. The controller's existing HTML projection creates the view for each structural render; the adapter mounts it after the Assets slot inside the app. The controller retains its delegated events and Session ownership. This does not make the view persistent or movable.

This is a fixed-placement adapter, not relocation, a profile system, independent left/right drawers, or a new feature controller. Existing cross-side exclusivity, preference format and workspace geometry remain in force. Actual browser/native, active IME and in-flight asset integration remain separate acceptance work.

Each existing adapter declares its fixed supported side; the controller checks the declaration against that capability before it reads preferences or attaches DOM. This is not a movable-placement policy: a different side is rejected. Assets owns its body portal and in-flight work; Shared Colors owns its input/IME draft, app-level events and Session envelope; the host owns focus, pointer and drawer visibility. The Colors adapter now consults that owner before switching or closing while composition is active, and its input guard protects the focused draft before pointer blur and Viewer activation. When a name change occurs during a pointer transition, the existing deferred-render path keeps the destination alive until the click finishes. Synthetic-composition and pointer behavior has been checked in Windows Chrome; physical IME and native WebView2 remain unverified. This bounded check does not establish safety for relocation, pointer capture or asynchronous file work.

`attach` checks the new root and its required canvas, right panel and tools before detaching the current host. An incomplete target leaves the previous host and queued restoration in place. This does not reconstruct DOM that a caller already removed, or implement relocation or active-edit migration.
