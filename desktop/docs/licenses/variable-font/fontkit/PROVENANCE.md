The official [npm version metadata](https://registry.npmjs.org/fontkit/2.0.4)
identifies gitHead `fbf3b9ef21eebd219eb73e666faed573af0fba09`. The complete
[pinned upstream source archive](https://codeload.github.com/foliojs/fontkit/tar.gz/fbf3b9ef21eebd219eb73e666faed573af0fba09)

filename matches, and npm distribution integrity are in `upstream-evidence.json`.

The exact [README](https://github.com/foliojs/fontkit/blob/fbf3b9ef21eebd219eb73e666faed573af0fba09/README.md) and
[package.json](https://github.com/foliojs/fontkit/blob/fbf3b9ef21eebd219eb73e666faed573af0fba09/package.json) are retained
byte-for-byte as `upstream-README.md` and `upstream-package.json`. They declare MIT,
but contain no full project copyright/permission notice. The source tree has no
project-level LICENSE, COPYING, COPYRIGHT, or NOTICE under any capitalization.
The only notice-named files are licenses for unrelated test font assets; they cannot be substituted for the fontkit code license.

The installed npm package was independently inspected with the same outcome.
No invented copyright years or another project's notice are substituted.
The package explicitly declares MIT. npm supports SPDX identifiers in package.json;
absence of a separate LICENSE file is not absence of licensing. The remaining
uncertainty is how the final bundled application carries the declared MIT terms
and available exact attribution/notices. This is a release-notice packaging review,
not a legal prohibition or a stop on development. See ../README.md for canonical
npm/SPDX references.

A content scan outside bundled test-font data found no project copyright line
or full MIT permission grant. Fontkit matches in test assertions describe font
metadata, not ownership of the library code.
